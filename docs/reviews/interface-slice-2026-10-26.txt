6. NOT DONE, AND WHY
--------------------
- Task side panel (the prototype's third zone) and a full-screen task sheet on phones. Instead, picking a task opens its conversation and scrolls to it. This saved scope; the cost is empty margins at 1440 (rubric 7 at 3).
- File versions (v1/v2/v3 with selection) for revised documents. No backend keeps file versions; a revision overwrites the file. The task shows each version's reply.
- "Edit wording" on a preference card, and removing a preference directly. Remove sends a chat request, which stages the policy_forget card; there is no direct route.
- "Ask again" on an expired card re-asks the model; there is no re-stage API.
- Step-level progress for background jobs. The scheduler emits no live events, so the task shows hand-off time and the goal's note.
- Screen reader, 200–400% zoom and real-device tests. Not run (same caveat as the review).
- 1280, 1920 and 360 viewports were not re-walked; only 1440 and 390 as asked. Layout is fluid, but this is unverified.
- U10 (connectors) and U11 (warm-start) were not walked. The code is unchanged; Connect lives in Settings and the warm-up is started from Settings.
- U02 at 390 was checked to the hand-off only, so the phone did not wait 20 min for the result.


7. BACKEND GAPS HIT (for the next backend slice)
-----------------------------------------------
1. The step detail is cut at 120 characters (agent.ts emit('step')), so a long granted-folder path loses its file name. The interface names the folder ("granted (your folder)") but cannot name the file.
2. Background and scheduled runs emit no live stage events (no liveRuns entry), so their progress is coarse.
3. After a background run hits its budget, the resume chain posts a second result ("stuck", "can't confirm the file") and stages check-script cards. Seen twice in U02. The owner then sees a correct file plus a "problem".
4. One request can still make several jobs. The B3 twin gate misses differently worded instructions (U03: 3 weekday jobs) and one-offs a minute apart (U04: 6). "Every 5 minutes" was scheduled as a one-off in 3 of 3 U04 attempts, while the reply said "every 5 minutes"; the claim check did not catch it.
5. The work note (serve.ts workNote) pulls unrelated chats into an open background goal. In U06 attempt 2 and U09 at 1440, the run wrote the board briefing instead of answering.
6. agent.ts:2549 hard-codes "the approvals panel in the app, or the button in Telegram". The interface filters it out when Telegram is not connected (F20); it should be fixed at the source.
7. Exploratory reads and check scripts are still staged as owner decisions (F19, backend part): listing a folder with PowerShell, and python "does the file exist" checks.
8. `revise: <turnId>` targeting is not built. The Revise box sends a normal message that names the task and quotes the answer, which worked in all runs.
9. Answering an offer ("Work on it") is not recorded on the offer turn. The interface links the offer to its goal by words and time, so another device shows it as handed over.
10. Ended cards in /api/approvals `recent` carry `at` but not `expiresAt`; the interface shows the expiry from `at`.
11. Stop has no server Resume. "Continue from where it stopped" sends a message, which worked.
12. Memory concepts carry "person unknown: …". The interface strips the prefix and files these under About you, but the people record still lists fields as "missing" while those notes exist.
