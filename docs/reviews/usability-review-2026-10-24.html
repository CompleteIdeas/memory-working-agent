1. Recommended interaction model

A task-centred workspace. Every piece of work (a question, a background job, a reminder, a watch, a change that needs approval) becomes a task with one state record. The chat, a Tasks rail (Needs you · Running · Scheduled & watching · Finished), a task panel and the return digest all read that same record. Desktop shows the rail, the conversation and the selected task side by side. Phones use a bottom tab bar (Chat · Tasks · Needs you · Memory), a one-line active-task strip and a full-screen task sheet.

Decisions inline, scoped and alive. Cards appear inside the task that raised them, one per proposal, each with its effect and an expiry clock time. Cards record their outcome (done and checked, declined, expired with Ask again, changed with re-review). The shared dock that covered the chat is gone.
Meaningful progress and a real Stop. "Step 2 of 3: Reading meeting-notes-oct.txt · 14s · Stop", the same in chat and rail. Stop distinguishes requested from effective and says what was kept.
Owner controls for schedules. Reminders, recurring jobs and watches are tasks with the owner's own words, the next run, the last result, and change time / pause / cancel / undo.
Steering and revision. A message sent mid-task asks once where it goes. Results are versioned artifacts with Revise.
Know what it can read. An "I can read" line above the input names the granted folder and chat files.
Coming back. A digest of Needs you / Finished / Problem / Coming up; a running turn survives a reload.

Preserved: the "Instrument" identity (bone, graphite, one signal colour, Archivo and Plex Mono), the "Work on it, get back to me" offer, the file viewer, server-kept conversations and memory recall. Changed: the navigation (Chat · Tasks · Files · Memory; Connect, Log and Warm-start move to Settings or specialist detail), text colour tokens for contrast, and every status and decision surface.

14. Model quality vs interface quality

The interface and the model's answers were judged separately. Where Luna had the files, its answers were correct and short (U09 twice, U02 briefing, U07 recall). Failures that belong to the model or runtime, not the UI: not finding the granted folder (also a context gap), 4 reminders for 1 request, hedged watch messages, refusing to cancel, and "make it shorter" applied to the wrong reply. The redesign does not make these correct. It makes them visible and correctable, and the backend items above are what would fix them. A different model was not tested.
