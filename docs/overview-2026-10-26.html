MWA at a Glance

A personal assistant that remembers. A cheap model runs the loop, a memory substrate (AWM) keeps what it has learned and decided, and a person stays at every gate that changes the world. This page covers what it does today, what has been measured, how it got here, and what is still open.

What it is

MWA is a self-hosted assistant you talk to in a web app, on Telegram, or by dropping a file in a folder. It answers from memory first, reads your files and the web when memory is silent, schedules reminders and watches, works on longer tasks in the background, and drafts email it never sends. Everything it writes, runs or sends outside the machine waits for your approval. It runs as one Docker container on a NAS or on Railway, with every secret and memory on a local volume.

The thesis under it: the capability for running long, messy work lives in the memory, not in the model. A cheap model primed by a studied memory answered what the team decided and why as well as a frontier model reading the files, at a forty-fifth of the cost. Where it still loses is judgment that needs figures the memory never stored.

What has been measured

Experience pilot: can a cheap model answer like a team member?

Eighteen questions about MWA's own record (lookups, synthesis, current state, rationale, apply, judgment), three repeats each, judged by Gemini 3.8 Flash. Luna is the cheap model, Sol the strong one.

Gaps and open decisions

Release the interface as 0.8.0

The task-centred workspace from the usability review is built and scored 85 of 100 on the review's own rubric, replayed on the real runtime, with zero accessibility violations. It changes every screen, so it is a version of its own. Also on the branch: frames in the snapshot, the file check, and the model that can look at the page.

decision · release
Browser review: closed out

All sixteen findings have a fix on the branch: the redirect guard, one tab per conversation, forms surviving the go-ahead turn, dropdowns, scrolling, honest cut notes, plain labels, the background phrase, the browsing guide, the unattended allowance, frames and cookie walls, the file check, Stop and steer in the app, and a model that can look at the page a few times a run. Measured: the NPR front page answered 2 of 2, a layout question answered from the picture.

done · browser
Usability: built to 85, with a tail

The interface slice landed at 85.0 on the real runtime (baseline 30, prototype 71). Left for later: a task side panel on wide screens, file versions for revisions, editing a preference from its card, step-level progress for background jobs, screen-reader and zoom tests.

open · interface tail
Judgment questions still miss the figures

Three of eighteen pilot questions fail on every memory arm because the deciding number was never stored. Two figure passes stored it and lost elsewhere. The fix has to enrich the fact memories, not add memories.

open · study coverage
Released: 0.7.0

Bumped, written up in the changelog, tagged, merged and deployed on 2026-10-25. The build queue's "unmerged" notes for BL-70 to BL-74 were stale and are corrected.

done · release
Automatic approvals stay off

BL-72's Clef reviewer is built. Live approval waits for shadow data from real runs, which nobody has reviewed yet; BL-36's claim check is in shadow for the same reason.

waiting · shadow review
Every five minutes became once: fixed

The interface replay saw six one-off jobs from one "every 5 minutes" request. The schedule step now holds a one-off once when the person's words give an interval, and books it as a repeat when the model takes the hint.

done · scheduler
Background jobs: what the interface replay surfaced

No live step events for background runs; a run that hits its budget resumes and then posts a "stuck" result and check-script cards; the server's open-work note pulls unrelated chats into an open goal; exploratory reads are staged as decisions; a reworded or near-time duplicate job slips past the twin check.

open · background work
Cost reporting overstates

costUsd on a run counts more than the provider charged. Noted during the pilot, not yet traced.

open · observability

How often thinking time runs and its cap await a decision; the rulebook test needs Robert's own files; the curiosity loop and "think hard once" are scoped, not built.

decision · scope

What works and should be kept

The review's positive finding, and the pilot's: approvals a person gives are understood and trusted; the Files area and granted-folder reads work once the agent knows about them; memory of a stated preference carries across conversations; a cheap model on studied memory answers decisions and reasons like a team member at a cent an answer; the injection fence holds on the models MWA recommends.
